Reconstruction §3 · initial T239 / L238 deployment, not a model-wide limitOptional

The INT8 graphs still needed CPU fallback.

After fixing the shapes, unsupported quantization operations prevented full HTP execution.

ComponentWhere it ran
Duration predictorCPU
Text encoderCPU
Vector estimatorQNN HTP + CPU
Rewritten vocoderQNN HTP

What remained in the way

  • DynamicQuantizeLinear
  • MatMulInteger + weight dequantization
  • One unsupported Softplus

Each estimator call: 21 HTP partitions
plus 136 CPU nodes.

Numerical gate failed. Exact listening samples were accepted; this was still a hybrid route.

4 / 11
Reconstruction §4 · experiment 0010 · a partial success, not the final routeOptional

We switched to the official FP32 graphs.

They avoided the INT8 export’s unsupported quantization operations.

Packaged INT8 estimator

Its execution path included:

  • DynamicQuantizeLinear
  • MatMulInteger
  • Weight dequantization operations

Official FP32 estimator

Floating-point operations instead of that quantized execution path.

QNN could handle those operations.
Only Softplus remained unsupported.

We replaced that remaining operation:
Softplus(x) → max(x, 0) + log(1 + exp(-abs(x)))

All four graphs ran on HTP. FP32 source; FP16 requested. Per-operation precision was not measured.

Reconstruction §9 · larger-context work → 0036 · not a successful long-speech resultOptional

We followed the provider’s long-text recipe.

Instead of passing the whole chapter to a single synthesis call.

  1. Group whole sentences toward 300 characters.Split the raw text before normalization.
  2. Normalize and index each group.Use explicit English and the M1 voice.
  3. Synthesize each group separately.Eight refinement steps · speed 1.05.
  4. Keep each full waveform and join the segments.Insert 0.3 seconds of silence between them.
