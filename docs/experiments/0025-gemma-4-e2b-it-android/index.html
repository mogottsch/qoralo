Experiment description#

The project wanted trustworthy CPU and GPU measurements for an official Gemma mobile deployment on the Galaxy S23 Ultra without mistaking cached prompt work or a fallback route for real performance. The final experiment therefore answers two linked questions: can the official Gemma 4 E2B IT LiteRT-LM artifact complete the fixed Android campaign on each neural backend, and can every repeated request be isolated while the expensive model and Engine remain loaded?

Following an explicitly approved route amendment, both published arms use the official generic gemma-4-E2B-it.litertlm artifact: 2,588,147,712 bytes, SHA-256 181938105e0eefd105961417e8da75903eacda102c4fce9ce90f50b97139a63c. The CPU arm uses four threads. The GPU arm requests Backend::GPU, with kGpu as the only LiteRT hardware accelerator bit and no CPU fallback bit. Both use LiteRT-LM v0.16.1, an 8,192-token route capacity, thinking disabled, and the runtime's exact greedy-equivalent CPU TOP_P(k=1) sampler. The embedded tokenizer produces 171 short, 595 medium, and 1,930 long input tokens, all fitting with the unchanged 2,048-token output ceiling.

Each arm retains one loaded Engine, destroys the prior Session, and creates a fresh Session before every later logical request. Session creation is measured separately and excluded from TTFT, prefill, decode, and total-request timing. The owning experiment README, route contract, canonical CPU result, and canonical GPU result preserve the exact route and claim boundaries.

Progress#

The experiment first pinned the model, deployment, tokenizer/template, runtime, runner, libraries, workload hashes, and authorized SM-S918B device. Host and 64-token phone smokes established bounded viability only; neither is used as a canonical campaign distribution.

The first 16-request CPU attempt exposed a critical reset problem. RewindToStep(0) retained reusable prompt/KV state and produced impossible repeated-prompt prefill rates. The diagnostic was rejected. Bounded probes showed that retaining one Engine while creating a fresh Session restores full prompt work, and Moritz approved that protocol-v2 isolation strategy. The final CPU campaign then completed one first short plus five loaded-route requests per tier. All 16 requests used the correct input counts, ended at EOS, retained exact output bytes, and passed the narrow sensible-text check. Its 42-file manifest binds the evidence.

The original dedicated gemma-4-E2B-it-gpu.litertlm Artisan artifact was assessed first. LiteRT-LM switched the request to GPU_ARTISAN but the pinned open-source runtime lacked the required legacy TFLite engine, so execution stopped before inference. No request ran, no provider bound, and no metric was published. That durable Artisan blocker remains historical rather than being overwritten by the amended route.

Moritz then approved the official generic artifact with Backend::GPU. A provider-bound one-request smoke established viability only. The first canonical launch attempt stopped before any request because its configured cache directory did not exist; the missing-cache diagnostic is non-counted. A completely fresh succeeding campaign write-probed the cache and completed the canonical 1+5+5+5 shape. From that campaign process, provider binding is proven by the GPU-only/no-fallback accelerator mask, fully delegated single-delegate hint, mapped libLiteRtGpuAccelerator.so and Qualcomm/Adreno OpenCL/GLES libraries, and open /dev/kgsl-3d0. All 16 requests ended at EOS with exact retained outputs and fresh-Session isolation. Its 47-file manifest binds the result.
